# L0 შეკრება — პირველი 25-ლინზიანი სინთეზი

2026-09-05 · `experiment/representation-search` · კვლევითი ჭრილი, არა მიღებული ოპტიმიზაცია.

## კითხვა და საზღვარი

მიზანი არის 25 ხედის ერთობლივი მიგნებებიდან ახალი კანდიდატების გამოყვანა,
არა წინასწარ არჩეული ორი ალგორითმით კვლევის ჩანაცვლება.
პირველი ობიექტია `a+b+carry_in`: `M=2^(word_bits*limbs)`,
`0<=a,b<M`, `carry_in∈{0,1}`;
გამომავალია `low∈[0,M)` და ცალკე `carry_out∈{0,1}`,
სადაც `a+b+carry_in=low+M*carry_out`.

ეს ჯერ არც Fp არის და არც Fn. სხვა მოდულით reduction-ის შემოტანა ობიექტს ცვლის,
თუ მთელი low+carry გამომავალი ზუსტად ვერ აღდგა. მარტო ძველი carry ბიტი არ კმარა:
0 და q<M ორივე იძლევა 0 mod q-ს და carry=0-ს, მაგრამ განსხვავებულ low-ს.
ზუსტი decode მოითხოვს დაკარგულ quotient-ს ან ეკვივალენტურ ინფორმაციას. C++-ის კონტროლი უცვლელი
`add64`-ია; 4×64 ვარიანტი მისი harness-კომპოზიციაა, არა production field-add.
Python serial/prefix მოდელები C++ კონტროლისგან ცალკე რჩება.

**25/25 ხედის განხილვა არ ნიშნავს 25/25 დახურულ კითხვას.**
ქვემოთ თითოეული ხედი ან მტკიცებულებას უკავშირდება, ან კონკრეტულ ნაკლულ
შემოწმებას. ეს არ არის შესრულებული 625-უჯრედიანი W×V ექსპერიმენტი.
რეესტრის მანქანური შემოწმება ამოწმებს წყაროს იდენტობასა და ჩანაწერის წესებს,
არა ყველა ტექსტური დასკვნის ჭეშმარიტებას.

## სტრუქტურული მიგნება: რა ინფორმაცია გადადის carry-ით

ციფრისთვის `a_i+b_i=B*g_i+r_i`, `p_i=[r_i=B-1]`.
ამ საზღვრებში `g_i` და `p_i` ერთდროულად 1 ვერ იქნება;
შემომავალი carry-ის გავლენა არის `C_i(c)=g_i OR (p_i AND c)`.

ორივე შესაძლო შემომავალი ბიტისთვის მხოლოდ სამი ქცევა გვრჩება:
**K** — ყოველთვის 0; **P** — შემომავალი ბიტი; **G** — ყოველთვის 1.
ფუნქციების კომპოზიცია ასოციაციურია, მაგრამ რიგი მნიშვნელოვანია.
ეს არის ცნობილი carry/prefix სტრუქტურა; ახალ მათემატიკურ აღმოჩენად არ ვაცხადებთ.
მცირე დომენების შესრულებადი შემოწმება და კონტრმაგალითები ცალკე
[carry-ის კვლევაში](CARRY_STRUCTURE.md) ინახება.

აქ ორი განსხვავებული ინფორმაციული საზღვარია:

- K/P/G საკმარისია მხოლოდ **carry-ის გადაცემისთვის**, არა დაბალი შედეგის აღსადგენად.
  დაბალი ბიტებისთვის საჭიროა საწყისი operand-ები ან შესაბამისი შუალედური state.
- ცნობილი carry-in-ის serial გზას ერთი მიმდინარე carry ბიტი ჰყოფნის.
  სამი ფუნქციის წარმოდგენა მის state-ს ავტომატურად არ ამცირებს.

მეორე შეზღუდვა: ორ operand-ზე საკმარისი ერთი carry ბიტი მრავალჯერადი
შეკრების ყველა მაღალი ნაწილისთვის საკმარისი აღარ არის. მაგალითად,
`(M-1)+(M-1)+(M-1)=3M-3`; `M>=3`-ზე მაღალი კოეფიციენტი 2-ია.
`low`-ის დატოვება და წინა carry-ის გადაგდება value-preserving გარდაქმნა არაა.
Lazy/carry-save region-ის bounds უნდა მოვარგოთ მთელ region-ს.

## ერთობლივი სინთეზი → შესამოწმებელი ჰიპოთეზები

ყველა ქვემოთ ჩამოთვლილი პუნქტი არის **HYPOTHESIS**.
ახლანდელი პრიორიტეტი კვლევის ინფორმაციულ სარგებელს ნიშნავს, არა performance rank-ს.

| ჰიპოთეზა | რომელი მიგნებები აერთიანებს | უარყოფის/მიღების საზომი |
|---|---|---|
| H01 — ხელახლა გამოთვლა თუ შენახვა | V13/V14/V18/V19 + W16/W25: GP/raw-low შუალედურის შენახვა შეიძლება spill-ს ქმნიდეს | იგივე სრული output-ით materialize/recompute; დათვლილი დამატებითი load/ALU და ახალი interleaved control |
| H02 — ლოკალური ბლოკები + carry summary | V05/V12/V13/V15 + W17/W18/W25: ბლოკის შიგნით serial, შორის ასოციაციური summary | block partition-ის invariants, სრული low/carry, ყველა boundary და scratch; პატარა4-limb-ზე წაგებაც დარჩება |
| H03 — დაგვიანებული normalization მთელ region-ში | V03/V05/V08/V15/V16 + W04/W09/W11/W19 | გაფართოებული state-ის bound, ყველა intermediate/carry, მხოლოდ ერთხელ decode-ის სრული ფასი |
| H04 — დამოუკიდებელი ნაკადების განლაგება | V06/V10/V17/V19/V21 + W08/W22/W23 | იგივე batch, AoS/SoA/plane გარდაქმნის ჩათვლით; alias/CT/portability ცალკე |

H01/H02-ის prefix შუალედურებთან მოგება ჯერ არ ნიშნავს ორიგინალ serial-ზე მოგებას:
ორიგინალს შეიძლება საერთოდ არ სჭირდებოდეს ის შუალედური მასივი, რომელსაც ვაუქმებთ.
Cache-ში operand-ის ხელახლა წაკითხვა და DRAM-იდან ხელახლა წაკითხვა ცალკე რეჟიმებია.
H03 უკვე სხვა, მრავალოპერაციულ region-ს ითხოვს; ერთ შეკრებასთან პირდაპირი
შედარება უკანონო იქნება. H04 batch throughput-ს ეხება, არა ერთი ხელმოწერის latency-ს.

კანდიდატს წინ უძღვის boundary/witness, equivalence, invariants/CT და რესურსის
შემოწმება; მხოლოდ ამის შემდეგ იქნება დროის/მეხსიერების/ოპერაციების Pareto შედარება.
არც „მეტი ოპერაცია“ იბლოკება წინასწარ, არც „ნაკლები სიღრმე“ ცხადდება გამარჯვებულად.

## ამ ჭრილის ახალი შესრულებადი შედეგი

[carry_structure.py](carry_structure.py)-ის დამოუკიდებელ default replay-ში:
**10 განლაგება, 18,248 input triple განლაგებების ჯამში, 55,528 სრული output
შემოწმება, 0 უთანხმოება**. განლაგებებს შორის ზოგი მათემატიკური input მეორდება;
18,248 უნიკალურ სამეულს არ ნიშნავს. მაქსიმუმია 6 ბიტი თითო operand-ზე,

ასოციაციური კომბინაცია და სამი წყვილის გარჩევადობის მოწმე.
